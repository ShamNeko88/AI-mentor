# 目的
相談の過程を記録し、復習・問題作成・振り返りの材料にする。

# 実行手順

## STEP 1：内容を整理する
このセッションの会話から、次を抜き出す。
- テーマと目的
- 分類（勉強 または 業務）
- 学んだこと・決まったこと
- つまずいた点、誤解していた点
- 残っている疑問
- 次にやること

会話にない内容は書かない。推測は「推測」と明記する。

## STEP 2：ノートを保存する
output/notes/<カテゴリ>/yyyymmdd_テーマ.md に保存する。
- カテゴリは技術分野（AWS、Snowflake など）。勉強/業務の区別はフォルダではなくタグで行う。
- 保存前に output/notes/README.md（カテゴリ一覧）と既存フォルダ一覧を確認し、近いカテゴリがあればそれを使う。（表記の揺れ防止）
- 該当するカテゴリがない場合は「その他」に保存する。新しいカテゴリフォルダが必要なときは、作成前にユーザーに確認する。
- 新しいカテゴリフォルダを作ったら、output/notes/README.md に「- カテゴリ名: 内容の説明（一行）」を追記する。README.md がなければ作成する。
- 複数のカテゴリにまたがる場合は、主なカテゴリのフォルダに保存し、他のカテゴリはタグに入れる。
- 同名ファイルがある場合は上書きせず、追記するか別名にするかをユーザーに確認する。
- 機密情報、APIキー、個人情報は書かない。

## STEP 3：報告する
保存先と、ノートの要点を3行以内で伝える。

# ノートの形式

```markdown
# テーマ名

- 日付: yyyy-mm-dd
- 分類: 勉強 / 業務
- タグ: （キーワードを数個）

## 目的
何のための相談か。

## 学んだこと・決まったこと
- 

## つまずいた点・誤解していた点
- 

## 残っている疑問
- 

## 次にやること
- 

## 復習・問題作成用メモ
後で問題にしやすい重要ポイント（用語、手順、判断基準など）。
- 
```
